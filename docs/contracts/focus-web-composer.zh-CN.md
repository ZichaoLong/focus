# Focus Web 输入框

文档角色：中文规范源。英文同步副本：`docs/contracts/focus-web-composer.md`。

## 展示状态与唯一 owner

`ConversationPane.vue` 的 `setComposerSurfaceMode` 持有 compact、expanded、hidden 展示状态，
同时管理新对话与已有会话的输入框入口。`Composer.vue` 通过事件请求切换；`ChatDock.vue` 只转发
展示状态与操作。`useComposerDraft` 继续持有同一输入框、会话草稿及保存边界。切换展示状态不创建
第二份草稿，不重新挂载或移动 textarea，不修改发送快捷键、提交和回执语义。

窄屏普通输入框保持约四行，额外文字在框内滚动；用户可显式展开。宽屏维持原有约 70vh 的展开
输入区。展示状态不持久化，切换会话或跨越窄/宽布局边界回到 compact，草稿继续遵循原会话作用域。

## 键盘编辑与页面边界

普通与展开输入框中的 ↑、↓、PgUp、PgDn 保留浏览器原生的光标移动和文本滚动行为，不能导致应用框架
横向滚动、左侧线程列表移出视口或改变草稿内容。固定应用框架只裁切溢出，各内部面板分别持有
自己的滚动范围。输入框不保存或召回已发送输入；到达文本开头也不切换为历史浏览。
斜杠和文件提示菜单打开时，↑/↓ 仍用于选择菜单项。历史 Prompt 通过既有历史按钮查找和复制。

`ConversationToc.vue` 在空间不足时保留导航节点及其位置测量，但隐藏内容和悬停区域不得撑宽
应用框架。窗口变宽后继续使用同一节点恢复导航，保持 Prompt 历史入口可用。被宽表格遮挡时
保留导航原有尺寸，供既有重叠判断使用。

## 窄屏展开编辑

窄屏展开后利用网页可见区域：暂时收起线程选择栏、提交记录栏和会话正文，只保留简短的当前会话
标题（新对话显示“新对话”）、明确的“收起”按钮和原输入工具栏。正文保持挂载但不可见、不可交互；
不卸载历史、重新读取线程或改变正在阅读的锚点。新对话的欢迎区域和工作区选择暂时收起。

展开输入区按剩余高度伸缩，不受 280px 或 34dvh 上限限制，也不依赖文字多少。复用
`focusViewport.ts` 的 `createFocusViewport` 提供的可见高度与顶部偏移：键盘弹出、收起、浏览器
地址栏变化时重新分配编辑空间，工具栏保持可见，长文只在 textarea 内滚动。附件列表有界滚动，
斜杠和文件提示菜单显示在编辑区以内。浏览器自身的地址栏与系统键盘仍由浏览器管理。

展开/收起保持同一 textarea、草稿、选区及中文输入状态。收起时不强行唤起已经关闭的键盘，并由
原正文滚动 owner 保留阅读位置；发送等新的用户意图可按既有规则回到最新。原会话已切换时，迟到
的布局回调不能恢复旧线程锚点。

`FocusApp.vue` 只消费会话组件派生的展开状态来收起导航；错误、连接与权限提示仍可见。待回答问题
和审批优先显示，暂时让出展开布局，保留原输入框 owner 和草稿；处理完毕后可恢复展开编辑。
确认未发送（`known_no_effect`）时保留原文与展开状态；当前草稿的提交回执允许清空时才收起。结果不明
仍沿用 [Prompt mutation recovery](./focus-web-prompt-mutation-recovery.zh-CN.md) 的身份、回执和恢复边界，
不因布局变化重新允许发送同一内容。

## 验证

浏览器回归覆盖窄屏可用空间、可见视口高度/偏移变化、选区、输入法事件不误发送、原 textarea 身份、
草稿与正文位置、失败/成功发送、新对话及窄/宽布局切换；桌面回归覆盖普通/展开输入框的原生
PgUp/PgDn、侧栏位置和导航隐藏/恢复。桌面窄屏和模拟键盘尺寸不能替代鸿蒙等
设备的真实输入法、键盘动画和浏览器绘制验证。
